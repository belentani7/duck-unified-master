# DUCK ECOSYSTEM — VISUAL DNA

> Canonical visual direction for every future Duck Ecosystem surface. This document is a design contract, not a moodboard.

## 01. Core idea

Duck is not presented as generic SaaS. It should feel like a **private creative machine**: part recording studio, part operating system, part control room, part archive, part futuristic instrument.

The visual language must communicate:

- premium music production
- tactile hardware + precision software
- dark-room intimacy
- cinematic confidence
- controlled complexity
- evidence over decoration
- human creativity augmented by machines

## 02. Visual grammar

### Palette

- Absolute black / near-black foundations.
- Warm white / bone typography.
- Metallic neutrals: graphite, brushed steel, gunmetal.
- Very restrained signal accents: electric green, amber, or ultraviolet may identify system state, but never become the dominant brand color.
- No rainbow gradients. No generic startup-blue UI.

### Materials

Black glass, smoked acrylic, brushed metal, anodized aluminium, dark rubber, subtle grain, studio-console surfaces, waveform traces, rack indicators, thin technical lines.

### Light

Low-key cinematic lighting. Large areas of darkness. Edge lighting and controlled highlights. Glow means state, not decoration.

### Typography

Use a strong grotesk/sans family with a technical secondary face. Oversized editorial headlines, compact uppercase labels, numeric telemetry, generous tracking for system labels. Never use novelty sci-fi fonts for body copy.

### Composition

Asymmetrical but disciplined. Large negative space. Horizontal control rails. Dense information islands separated by quiet zones. Interfaces should feel like instruments rather than dashboards.

## 03. Motion

Motion is functional:

- scan = discovery
- pulse = live state
- sweep = analysis
- orbit = relationship
- lock = approval
- stream = event
- fade = unavailable

Avoid decorative particle explosions and gratuitous parallax. Motion should explain the machine.

## 04. Image direction

Photography/imagery should evoke a dark premium studio at night: microphones, faders, cables, monitors, speakers, hands, hardware, waveform displays, artists and producers. Faces remain human and editorial. Technology is physical and believable.

## 05. UI primitives

- `SystemHeader`: identity + connection + environment
- `CommandBar`: intent input
- `SystemRail`: active systems and health
- `CapabilityMatrix`: what the ecosystem can actually do
- `ProjectCard`: project identity + truth state
- `SignalPanel`: audio/system telemetry
- `EventStream`: chronological machine memory
- `ProvenanceBadge`: source repository + evidence
- `ModeBadge`: REAL / SIMULATED / PLANNED
- `ApprovalGate`: human authorization boundary
- `AdapterCard`: external system connection
- `MachineDiagram`: orchestration flow
- `ArchiveDrawer`: original systems/assets remain addressable

## 06. Truthful visual states

REAL = visibly connected and evidence-backed.
SIMULATED = visually distinct, explicitly labelled, never presented as live.
PLANNED = future capability, visually quiet and non-deceptive.
UNKNOWN = missing evidence; never fill the gap with invented data.

## 07. Landing page narrative

1. **Opening:** DUCK ECOSYSTEM / THE CREATIVE MACHINE.
2. **Thesis:** many tools, one operating context.
3. **Machine:** Intent → Plan → Capabilities → Adapters → Action → Event → Memory.
4. **Systems:** Studio / Zion / Gema / Local / AI / Workforce.
5. **Reality:** show REAL, SIMULATED and PLANNED with evidence.
6. **Project flow:** demonstrate a real musical intent end-to-end.
7. **Archive:** originals are preserved; the ecosystem references, never replaces.
8. **Future tools:** every new tool enters through contracts + adapter.
9. **Closing:** one creative system, many instruments.

## 08. Anti-patterns

Never use: generic AI-brain imagery, stock SaaS illustrations, fake telemetry, fake waveform measurements, fake connected states, excessive gradients, rainbow neon, crypto aesthetics, cyberpunk clutter, claims of execution without evidence.

## 09. Accessibility and performance

High contrast. Respect reduced motion. Keyboard navigable. Mobile-first responsive layout. Decorative canvas/WebGL must have a semantic fallback. No visual effect may block the primary action.

## 10. Design law

**The interface should look like the machine is working, but every meaningful claim must be traceable to evidence.**
