# AI Builder Contract

Any AI extending this repository must read README, ARCHITECTURE, FOUNDATION and contracts before changing code.

## Rules

- Preserve original repositories.
- Use adapters instead of direct cross-system rewrites.
- Never claim simulated or planned work is real.
- Never fabricate external side effects.
- Never commit secrets.
- Respect permissions and approval gates.
- Emit provenance for consequential operations.
- Reuse canonical entities and capability names.
- Do not create parallel incompatible abstractions.
- Keep the visual language defined by VISUAL-DNA.

## Build order

CONTRACT → MODEL → ADAPTER → SERVICE → EVENT → UI → DEMO → TEST → DOCUMENTATION

## Missing capability

Create a truthful simulated path when useful, label it explicitly, and document the adapter required for a future real implementation.

## Definition of done

A feature needs a defined source of truth, mutation path, persistence behavior, permissions, truth status, error behavior, tests and provenance. A rendered card is not proof of functionality.
